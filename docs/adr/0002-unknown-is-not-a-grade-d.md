# Unknown 自成一族，不是 Grade D

裁决器原本把「确认两药无可替代性关系」和「我们没有能力判断这一对」都判为 Grade D，
差别只活在一个 `confidence` 字段和几句 caveat 里。这两件事对使用者的意义相反——
前者是结论，后者是缺口——所以我们把缺口拆成独立的 `U*` 族：
`U0` 标识符解析失败、`U1` 缺 ATC 编码、`U2` 映射不到任何 Orange/Purple Book 产品；
D 族只保留 `D1`（成分与 ATC 类均无关）和 `D2`（生物制品与小分子之间不存在法定等效路径）。

## Considered Options

- **保留 D，靠 `confidence` 区分。** 被否：`_GRADE_ACTION` 按等级字母索引，
  两种 D 因此拿到同一句行动建议；且任何按等级聚合的统计都会把「我们查不到」
  计进「已确认无关」，而覆盖率恰恰是本项目最需要诚实汇报的数字
  （5,000 个示例化合物中仅 1,020 个能匹配到 Orange Book 成分）。
- **只拆 `D1`，不新增字母。** 被否：保留了「D 就是没关系」这一误读，
  而这正是要修的东西。
- **新增 `U` 但只有一条规则，三种缺口靠 caveat 区分。** 被否：这是在新等级上
  重犯 `D1` 的错误——三种缺口对应的下一步动作互不相同（换标识符重查 /
  该药不在 ATC 体系 / 该药不在 FDA 数据中）。

同一个仓库里 `dose_form` 模块面对同一问题已经选过一次显式 `UNKNOWN`，
理由记在 `Changjin/dose_form/LIMITATIONS.md`：静默地把不确定当成结论，
正是肾上腺素十倍给药误差的发生方式。此处与之保持一致。

## Consequences

- Unknown 不在 `A→B→C→D` 这条有序轴上。多个产品行择优时它排在最末：
  某一行判不了，不削弱另一行从源文件字段读出的结论。
  若缺口发生在整对层面（`U0`/`U1`），本就不存在其他候选。
- Rule Catalogue 因此成为封闭枚举，并须有单一权威定义，
  供裁决逻辑、导出数据与界面图例共同派生。
  这顺带修掉 `C1` 与 `C2` 共用同一句行动建议的问题。
- 导出数据与前端的等级契约会变，需要一次有意的版本变更。
