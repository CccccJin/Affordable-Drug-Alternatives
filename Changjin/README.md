# Chemical Similarity Search API

This project is a high-performance cheminformatics API built with FastAPI, RDKit, and DuckDB. It allows users to search for chemically similar molecules using a SMILES string and supports filtering based on molecular properties.

## Core Technology Stack

* **Web Framework**: [FastAPI](https://fastapi.tiangolo.com/) - For building high-performance, easy-to-use APIs.
* **Database**: [DuckDB](https://duckdb.org/) - A fast, in-process analytical database, perfect for handling and querying the data in this project.
* **Cheminformatics**: [RDKit](https://www.rdkit.org/) - The industry-standard open-source cheminformatics toolkit for processing molecules, calculating fingerprints, and similarity.
* **Data Validation**: [Pydantic](https://docs.pydantic.dev/) - Used to define clear, robust data models and handle data validation and documentation automatically.

## Project Structure

The project's code structure follows the principle of separation of concerns, organizing different functionalities into independent modules.

| Path                 | Description                                                      |
| -------------------- | ---------------------------------------------------------------- |
| `main.py`            | FastAPI application entry point, contains all API routes         |
| `models.py`          | Pydantic data models, defining API request/response structures   |
| `chem.py`            | Wraps core RDKit chemical calculation logic                      |
| `db.py`              | Helper functions for database connection and queries             |
| `import_chembl.py`   | **One-time script for data preprocessing and database creation** |
| `index.html`, etc.   | Frontend files (HTML, CSS, JS)                                   |
| `chembl_data.duckdb` | The database file generated by the script                        |
| `sample_chembl.csv`  | The original sample data source                                  |
| `requirements.txt`   | The project's Python dependency list  

## Setup and Run

Because RDKit is not reliably available from PyPI on macOS, we recommend a Conda environment.

### Option A: Conda (recommended)

1. Create and activate environment (one time):
   ```bash
   conda create -n chemapi -c conda-forge \
     python=3.11 rdkit duckdb fastapi uvicorn pydantic pandas chembl_webresource_client
   conda activate chemapi
   pip install watchfiles  # for --reload
   ```

2. Start the API (from `prj.internship_202507/Changjin/`):
   ```bash
   uvicorn main:app --reload
   ```

3. Open:
   - Home page: http://127.0.0.1:8000/
   - API docs: http://127.0.0.1:8000/docs

### Option B: venv + pip (not guaranteed for RDKit on macOS)

If you cannot use Conda, you can try:
```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
# RDKit wheels may not be available; prefer Conda if this fails.
```

## Database: creating or using data

The API queries a DuckDB file `chembl_data.duckdb` with a table `compounds` containing:
`chembl_id, smiles, fingerprint_hex, mw, logp, hbd, hba`.

- If the DB file already exists, you can directly start the API.
- To (re)create the DB with sample data, either:
  - Run the preprocessing script:
    ```bash
    python import_chembl.py
    ```
  - Or use the initialization function in `app.py`:
    ```bash
    python -c "from app import setup_database; setup_database()"
    ```

## Endpoints

- `GET /` — serves `index.html` (simple front-end)
- `GET /properties` — returns filterable fields
- `POST /search` — similarity search by SMILES with optional filters
  - Example body:
    ```json
    {
      "smiles": "CC(=O)Oc1ccccc1C(=O)O",
      "threshold": 0.7,
      "filters": {"mw": {"lt": 500}}
    }
    ```
- `POST /resolve_name` — resolve common name to SMILES via ChEMBL
  - Example body:
    ```json
    { "name": "Aspirin" }
    ```

## Troubleshooting

- **ModuleNotFoundError: rdkit**: Install via Conda as shown above and ensure you start Uvicorn from the same Conda env.
- **ChEMBL `pkg_resources` deprecation warning**: Harmless; can be ignored. Updating the package in the future may silence it.
- **404 at `/`**: Ensure the root route exists in `main.py` (this repo includes it and serves `index.html`).
